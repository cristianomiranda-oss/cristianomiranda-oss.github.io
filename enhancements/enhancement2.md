## Origin of the Artifact

The category for enhancement two, algorithms and data structures, emphasizes the importance of creating algorithms that efficiently accomplish tasks for a given problem and uses the appropriate data structure that best fits a situation. For this reason, the same artifact, the CS-360 Mobile Architect and Programming course's final project, a weight tracker mobile application, is the basis for this enhancement, as it would greatly benefit from implementing algorithms to help enhance security and functionality, as well as ensuring that the data structure used for handling user data is integrated efficiently. Overall, the initial artifact is the weight tracker mobile application, and while it made use of algorithms to solve specific tasks, there are plenty of changes that can be made to add additional algorithms, as it can help improve the security, efficiency, and functionality of the artifact.

## Work Performed

For this enhancement, it builds upon the work performed in the first enhancement and focuses on improving the efficiency and security of the now web application-based weight tracker. The initial artifact was a great candidate for this category, as there were plenty of potential improvements and changes that could be made involving its use and application of algorithms and data structures, with the main improvements involving security. The initial artifact did not perform any validations aside from the initial login, which a malicious user could easily bypass. Transferring this same approach to the mobile application would be disastrous in terms of security, so a major focus was on adding validation checks that did not interrupt the flow of the application. To accomplish this, the middleware components of the project were adapted to use a security algorithm that decrypts user account data when needed and encrypts it for long-term storage to protect a user's identity. This encrypted data is called a payload and can safely be stored in the user's web browser, as any attempt to manipulate or read the data within the payload would fail without the security key, which is safely stored on the server and will be impossible to replicate or discover. Additionally, to further improve security for users, another security encryption algorithm was implemented that now hashes user passwords before storing them in the database. In the initial artifact, passwords were stored in plain text, so any user that accessed the accounts table would discover all passwords for the various users. Again, the switch to a web application makes this approach even more problematic since if any malicious user attempts to look at the user's database, they would see all user passwords. To fix this, a security algorithm module called bcrypt was added to the user account creation method within the database component. Hence, the web application instead stores an encrypted version of the password that cannot be reverse-engineered into the original plain-text password, so even if a password is viewed within the database, it cannot be properly read. The other work performed during this enhancement involved adding a sorting algorithm that improves the front-end component of the web application. The homepage that displays all user weight entries originally showed entries based on the time they were added to the database, with the newest being towards the bottom of the page. While the original artifact relied on the SQLite database to sort the entries in descending order based on the date field, and the Indexed DB database could replicate this feature, it limited users to viewing and managing their entries in a singular way. To improve this process, adding the sorting algorithm and the option for users to sort either ascending or descending and by either date or weight value improves the capability of the application, as it would be easier to view specific weight entries. The final improvement for this enhancement is improving the application's efficiency after it performs minor database interactions. In the initial artifact, after every update and deletion action, the database is reread, meaning that entries that were not affected are once again pulled from the database. Changing this approach to using a cached array will allow these minor changes to the database to be reflected in the cached array without having to reread all entries from the database. These actions of changing values within the array or removing an element within the array are not major enough to warrant refetching from the database, so relying on updating the cached array could greatly improve the user experience and reduce network traffic. In the end, this artifact was chosen due to the potential improvements that could be made to its processes using different algorithms and data structures to improve its efficiency and functionality, as well as properly introducing various security measures through specific security algorithms.

## Enhancement Outcomes

For this enhancement, many improvements were made using various algorithms, and the application's efficiency was also enhanced through better handling of the used data structure. Based on the work performed, the achieved course outcomes were the third and fifth course outcomes, as the third involves integrating algorithmic principles to find optimal solutions to a problem while balancing them with their potential costs. The fifth is the strong emphasis on security measures and ensuring that all potential vulnerabilities and issues are properly addressed in a design to help maintain security. For the latter, the new integration of security measures to fix security issues from the original artifact satisfies this course outcome through the discovery of the issues in the initial artifact, mainly the lack of continued verification through the application and the insecure storing of user passwords, and applying the necessary change to fix these issues. Finding solutions to mitigate and remove these potential security issues using security practices and security algorithms ensures that users' data will be securely stored and handled. Finally, the third outcome was met through the security algorithms used to integrate the secure practices, such as the encryption algorithms for hashing passwords and generating JSON payloads, and through the integration of a sorting algorithm. In terms of the latter, this satisfies the course outcome as the chosen sorting algorithm was carefully selected based on its running time in even the worst-case scenario. The choice of using merge sort stems from considering that users will likely be adding a massive amount of weight entries, and while other sorting algorithms will be functional, they have significantly worse potential run times. Choosing the merge sort algorithm due to its O(n log n) run time ensures that, regardless of the initial order of the array, users will encounter consistent performance when sorting. Thus, as the third outcome emphasizes the use of algorithm principles and determines the best solution while minimizing tradeoffs, the time and effort spent on finding the best sorting algorithm for the given task and properly integrating it meets the outcome.

## Takeaways

After completing the work for the second enhancement, it highlighted how important proper security measures were, and how important it is to find optimal solutions to problems. For the latter, this work mainly showed me how, even though there may be multiple solutions to a given problem, some solutions are simply more efficient and better than others. This principle is highlighted in the initial artifact, as even though a majority of the same functionality in the web application is housed in the initial artifact, the web application implements these features in a way that is more efficient and easier to manage. For instance, even though storing passwords in plain text in the initial artifact was functional, it created multiple security vulnerabilities that could cause major problems, so it needed to be changed even if it was functional. Additionally, the focus on security created multiple challenges, as even though security is a focus, it needed to be implemented in a way that did not impede the process to avoid harming the overall user experience. In this instance, while it was necessary to validate the user's identity before allowing access to specific CRUD database methods, requiring the user to type in their password before every action would have been a major irritation. Even though it would improve security, it would be too negative in terms of convenience, so users would likely avoid using the application. Thus, before development began, the planning stage required a heavy focus on finding a way to meet security needs without harming convenience for the user, and this ultimately led to the integration of JSON web tokens that are stored asynchronously and sent asynchronously with each attempted database request. Overcoming this challenge further emphasized this principle and showed that the effort made in finding the best solution is worth it in the long run. In the end, this enhancement required a large amount of time and effort to achieve the defined goals, but the improvements it made to the web application make the effort worthwhile.
